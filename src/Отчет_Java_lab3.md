## Задача 1.10. Дороги

### Текст задачи

Измените сущности из задачи 1.3.3. Гарантируйте, что между двумя городами может быть только одна прямая дорога (другой путь может быть проложен только транзитом через другие города). Города можно создавать с указанием заранее заданных путей, в любой момент времени можно добавить новую дорогу в любой город и удалить имеющуюся дорогу.

### Классы `City_3` и `Path_3`

Город хранит название и список исходящих дорог. Каждая дорога содержит город назначения и стоимость. Первый конструктор `City_3` создаёт пустой список, второй копирует переданный список.

Метод `addPath()` ищет дорогу по имени города назначения и при совпадении выбрасывает исключение. Метод `removePath()` удаляет дорогу по тому же признаку и сообщает об ошибке, если её нет.

Проверка повторов действует при вызове `addPath()`. Конструктор со списком принимает пути без такой проверки, а `getPaths()` возвращает изменяемый список.

### Алгоритм метода `runTask1_10`

3. Добавить или удалить дорогу. В готовом примере после добавления пути из A в B стоимостью 5 повторная попытка добавить путь в B стоимостью 10 вызывает исключение.

# Задание 2

## Задача 2.5. Маршрут

### Текст задачи

Данная задача предполагает разработку новой сущности на основе той, что была получена в задаче 1.4.8 (Город). Сущность Город может быть доработана по своему усмотрению для более удобного использования.

Основная идея задачи в разработке такой сущности, которая будет представлять собой маршрут между двумя городами. Данный маршрут в любой момент времени можно получить как массив для дальнейшего использования. Сущность Маршрут имеет следующие характеристики:

- Имеет Город начала и Город конца пути. 
- Инициализация Маршрута может быть выполнена только если указана точка начала и конца пути. Если указано значение `null` — то ошибка. 
- Точку начала и конца можно изменить в любой момент времени, но они всегда должны существовать. 
- Может вернуть массив Городов, представляющий собой маршрут из начала в конец. Массив содержит все Города (в порядке очереди) через которые надо пройти что бы попасть из Города начала в Город конца, причем и начало и конец также содержатся в этом массиве.

  Алгоритм формирования пути в данном случае не существенен, можно выбрать вариант со случайным путем, путем проходящим через наименьшее число городов, или самым дешевым путем. Если путь найти невозможно – возвращается пустой массив. 
- Маршрут может быть приведен к строке, которая будет возвращать название всех городов маршрута в порядке очередности. 
- Создание объекта и изменение точек начала и конца выполняется за константное время O(1).

Воспользуйтесь картой городов из задачи 1.3.3 и выведите маршрут из Города F в Город D

### Класс `Route`

Конструктор и методы `setStart()` и `setEnd()` проверяют переданные ссылки на `null`.

Сам путь вычисляется при вызове `getRouteArray()`. Метод `findRoute()` обходит граф в глубину и запоминает посещённые города, чтобы избежать зацикливания. При попадании в тупик он убирает последний город из строящегося пути.

Метод `toString()` соединяет имена найденных городов через ` -> ` или возвращает `Маршрут не найден`.

### Алгоритм метода `runTask2_5`

1. Создать города и дороги вручную или выбрать готовую карту из шести городов.
2. Указать начало и конец, создать `Route` и вывести последовательность городов. На готовой карте обход из F в D даёт `F -> B -> C -> D`.
3. В готовом примере изменить начало на A и вывести обновлённый маршрут. При попытке передать `null` в `setEnd()` вывести сообщение об ошибке.

## Задача 5.1. Сложение

### Текст задачи

Разработайте метод, который принимает набор числовых значений и возвращает их сумму в вещественной форме. С использованием данного метода выполните следующие сложения:

- 2 + 3/5 + 2.3 
- 3.6 + 49/12 + 3 + 3/2 
- 1/3 + 1

### Метод `Task5Methods.sumNumbers`

Метод принимает массив `Number[]`. Для каждого элемента он вызывает `doubleValue()`, прибавляет результат к накопителю `total` и после обхода возвращает сумму типа `double`. Благодаря общему типу в одном массиве можно хранить `Integer`, `Double` и `Fraction_3`.

### Алгоритм метода `runTask5_1`

1. В ручном режиме ввести количество слагаемых от 1 до 10. Для каждого выбрать тип и ввести значение. Вещественные числа вводятся через точку.
2. Передать заполненный массив в `sumNumbers()` и вывести результат.
3. В готовом примере тем же методом вычислить `2 + 3/5 + 2.3`, `3.6 + 49/12 + 3 + 3/2` и `1/3 + 1`. Результаты при округлении до четырёх знаков — `4.9000`, `12.1833` и `1.3333` соответственно.

## Задача 7.3. Возведение в степень

### Текст задачи

Создайте метод принимающий две строки, в которых будут записаны числа X и Y. Возвращает метод результат возведения X в степень Y. Для преобразования строки в число следует использовать метод Integer.parseInt, а для возведения в степень метод Math.pow.

Вызовите разработанный метод передав туда параметры командной строки полученные точкой входа в программу. Реализуйте метод так, что бы для возведения в степень и преобразования строки использовались короткие имена статических методов.

### Алгоритм метода `Power.calculate`

1. При запуске с двумя аргументами `Main.main()` передаёт обе строки в `Power.calculate()`.

3. Вывести результат. При ошибке преобразования `Main` перехватывает `NumberFormatException` и сообщает, что аргументы должны быть целыми числами.
