# Задание 3 

## Задача 3.3. Города

### Текст задачи
Создайте сущность Город, которая будет представлять собой точку на карте со следующими характеристиками: 
- Название города 
- Набор путей к следующим городам, где путь представляет собой сочетание Города и стоимости поездки в него. 

Кроме того, Город может возвращать текстовое представление, в виде названия города и списка связанных с ним городов (в виде пары: "название:стоимость"). 

Используя разработанную сущность реализуйте схему, представленную на рисунке 2.

### Класс `City`
Свойства:
- `name` (String)
- `paths` (List<Path>)

Два конструктора: только имя (список пуст) и имя + готовый список путей. Метод `addPath(City, int)` добавляет новый `Path` в список. `toString()` строит строку вида `"Имя: A:5, B:7"`; если путей нет — только имя.

### Класс `Path`
Свойства:
- `destination` (City) — куда ведёт путь
- `cost` (int) — стоимость

`toString()` возвращает `"НазваниеГорода:стоимость"`.

### Алгоритм метода `runTask3_3`
Предлагается два режима.

**Ручной ввод:**
1. Считать количество городов (1–20).
2. Создать массив `City[]`, заполнить именами.
3. В цикле считывать пути (откуда, куда, цена) с проверками; выход — `from == 0`.
4. Вызвать `addPath` у соответствующего города.
5. Вывести итоговую схему.

**Готовый пример:**
1. Создать 6 городов A–F.
2. Добавить пути согласно рисунку 2.
3. Вывести каждый город через `toString()`.

### Замечание о повторных путях
Метод `addPath` не проверяет, есть ли уже путь в указанный город: он просто добавляет новый объект `Path` в список. Если пользователь введёт один и тот же маршрут дважды (например, A→B за 3 и снова A→B за 3), в списке окажутся два отдельных пути, и в выводе это отобразится как `A: B:3, B:3`.

Это поведение соответствует заданию: в нём не требуется ни запрещать дубликаты, ни заменять существующий путь новым. Каждый вызов `addPath` — это просто «добавить ещё одну запись в список путей».

Если бы понадобилось избегать дубликатов, в `addPath` следовало бы сначала пройти по списку и проверить, нет ли уже пути в тот же город. Тогда можно было бы либо заменять стоимость, либо отказываться добавлять повторный маршрут.

# Задание 5

## Задача 5.5. Дроби

### Текст задачи
Создайте сущность Дробь со следующими особенностями:
- Имеет числитель: целое число
- Имеет знаменатель: целое число
- Дробь может быть создана с указанием числителя и знаменателя
- Может вернуть строковое представление вида "числитель/знаменатель"
- Может выполнять операции сложения, вычитания, умножения и деления с другой Дробью или целым числом. Результатом операции должна быть новая Дробь (таким образом, обе исходные дроби не изменяются)

Затем необходимо выполнить следующие задачи:
1. Создать несколько экземпляров дробей.
2. Написать по одному примеру использования каждого метода.
3. Вывести на экран примеры и результаты их выполнения в формате «1/3 * 2/3 = 2/9»
4. Посчитать f1.sum(f2).div(f3).minus(5)

### Класс `Fraction`
Свойства:
- `numerator` (int)
- `denominator` (int)

Конструктор проверяет знаменатель: если 0 — бросает `IllegalArgumentException`.

Методы:
- `sum_fraction(Fraction)`, `minus_fraction`, `mult_fraction`, `division_fraction` — операции с дробью;
- `sum_value(int)`, `minus_value`, `mult_value`, `division_value` — операции с целым;
- `division_fraction` бросает `ArithmeticException`, если числитель второй дроби равен 0.

Каждая операция возвращает **новую** дробь — исходные не изменяются.

### Алгоритм метода `runTask5_5`
Предлагается два режима.

**Ручной ввод:**
1. В цикле создавать первую дробь, пока знаменатель не станет корректным (ловим деление на ноль `IllegalArgumentException`).
2. В цикле запрашивать операцию (1–4, 0 — выход).
3. Спросить тип второго операнда: дробь или целое.
4. Считать второй операнд.
5. В `try/catch` выполнить операцию. `IllegalArgumentException` — ошибка создания дроби, `ArithmeticException` — деление на ноль.

**Готовый пример:**
1. Создать `f1 = 1/3`, `f2 = 2/3`, `f3 = 3/4`.
2. Показать все операции с дробью и с целым.
3. Проверить `1/3 * 2/3 = 2/9`.
4. Посчитать цепочку `f1.sum(f2).div(f3).minus(5)`.

### Обработка ошибок

| Исключение | Когда возникает |
|---|---|
| `IllegalArgumentException` | знаменатель равен 0 при создании дроби |
| `ArithmeticException` | деление на дробь с нулевым числителем |
| `ArithmeticException` | деление на 0 (целое) |

Класс `Fraction` бросает исключения через `throw`, метод `runTask5_5` ловит их через `try/catch` и печатает сообщение через `e.getMessage()`. После исключения метод продолжает работать пока пользователь не введет правильное значение.
